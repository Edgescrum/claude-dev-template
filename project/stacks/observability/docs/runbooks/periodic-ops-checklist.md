# 半年ごとの運用棚卸し（4/1・10/1）

> cron が `#ops-digest` にリマインダーを投稿したら、上から順に確かめて結果を Issue（またはこのファイルの末尾の記録表）に残す。
> **期限切れは事前にエラーを出さない。** 気づくのは止まった後になる。

## 1. 期限があるもの

| 対象 | 確かめること | どこで |
|---|---|---|
| ドメイン | 有効期限・自動更新が ON・登録者情報 | レジストラ |
| 証明書 | 自動更新されているか（ホスティングが管理しているなら、その設定） | ホスティング |
| 外部 API のアクセストークン | 期限のある鍵（長期トークン・個人 API キー）の期限 | 各サービス |
| webhook の署名シークレット | 送信側と受信側で一致しているか（最近ローテーションしたなら両方） | 各サービス / ホスティングの環境変数 |
| 支払いカード | 有効期限・登録先（全サービスで同じカードなら一覧にする） | 各サービスの請求設定 |
| 無料枠・プランの条件 | 上限と「超えたら何が起きるか」が `docs/bootstrap.md` の上限表と一致しているか | 各サービスの料金ページ |

## 2. 監視が生きているか

| 対象 | 確かめること |
|---|---|
| エラー監視 | 直近にイベントが**受信側に**届いているか（0 件が続いていたら DSN を疑う） |
| 行動分析 | 本番プロジェクトの直近の件数が Query API で 0 でないか（キーの取り違え） |
| 外形監視 / cron 監視 | 監視対象の一覧が現在の構成と一致しているか・通知先が生きているか |
| 運用通知 | 3 チャンネルの webhook が生きているか（テスト投稿） |
| 送信枠 | 外部の送信枠の消費の推移（上限に近づく傾向が無いか） |

## 3. 権限と鍵

- 退任者・使わなくなった連携のアクセス権を外したか
- 運用者が保管している鍵の控えが、ホスティングの現在値と一致しているか（読み返せない変数は特に）
- 本番の認証情報がエージェントの環境に渡っていないか
