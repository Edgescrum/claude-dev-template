## スタック: stripe

Stripe で課金（サブスクリプション / 単発決済）を行う。**価格の正は 1 か所だけ**（記入: 例 `src/lib/plan/pricing.ts`）に置き、
画面・メール・要件ドキュメントはそこを参照する。

### 鍵と環境

| 規則 | なぜ |
|---|---|
| 本番 = live 鍵、staging / 開発 = **test 鍵**。live 鍵を Preview・開発環境・エージェントに渡さない | test と live は別世界（顧客・商品・webhook endpoint がすべて別）。混ざると実課金が起きる |
| サーバー側のコードは鍵の接頭辞（`sk_live_` / `sk_test_`）と環境を突き合わせ、食い違えば起動・実行を止める | 環境変数の取り違えを実課金の前に止める |
| test のデータを作るスクリプトは `sk_test_` 以外で必ず停止する | 誤って本番に書かない |
| 本番の Stripe の設定変更（商品・価格・webhook endpoint）は、対象・内容・理由を示して運用者の許可を都度得る | CLAUDE.md の「本番環境へのアクセス規律」 |

### Webhook

| 規則 | なぜ |
|---|---|
| **生のリクエストボディ**で署名（`Stripe-Signature`）を検証してから処理する。検証できなければ 400 を返して何もしない | パース後の JSON では署名が合わない / 偽のイベントを処理しない |
| 同じイベントは再送されうる。**イベント ID で冪等**に処理する | 二重計上・二重付与を防ぐ |
| 到着順は保証されない。イベントの中身を信じきらず、必要なら API で最新の状態を取り直す | 古いイベントで新しい状態を上書きしない |
| **コードが処理するイベントの一覧を 1 ファイル（manifest）に置き、テストでコードの `case` と一致を検査する** | `case` を足したのに一覧を直し忘れる |
| **昇格のたびに、Stripe 側の endpoint の購読イベントが manifest を覆っているかを確かめる**（`docs/runbooks/release-supplement-stripe.md`） | 購読漏れはエラーを 1 件も出さない。イベントが届かないだけで、金銭的な実害が静かに進む |
| 取りこぼしの後始末として、Stripe と DB の状態を突き合わせる日次の照合（reconcile）を置く | 購読を正しくしても、配送失敗は起こる |
| 処理は `await` し終えてから 2xx を返す。失敗したら 5xx を返して Stripe に再送させる | 返した後の処理は打ち切られうる |

### 金額と状態

- **クライアントから来た金額・価格・数量を信じない。** サーバーが価格 ID・数量を自分の正（価格の 1 か所）から決めて Checkout / PaymentIntent を作る
- **支払いの成否はリダイレクト先の URL ではなく webhook（またはサーバーからの API 照会）で確定する。** 戻り先の画面は「処理中」を出すだけ
- 権限（プラン）は Stripe のサブスクリプションの状態から導く。DB の写しは webhook で更新し、食い違えば Stripe を正とする

### 解約

- 既定は**期間末解約**（`cancel_at_period_end`）。解約操作の時点では権限を落とさず、期間末に届くサブスクリプション終了の webhook で
  非公開化・権限の剥奪を行う
- 解約予約中であることを DB にも持つ（画面での表示と、ダイジェスト・解約予兆の集計に使う）
