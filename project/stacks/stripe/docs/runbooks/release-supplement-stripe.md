# runbook 補足: Stripe（webhook の購読イベントの突き合わせ）

> `docs/runbooks/release-and-hotfix.md` の R1〜R4 で、webhook の処理（`case`）に差分があるとき、
> および PR②（→ staging）・PR③（→ main）の前に毎回通す。

## なぜ昇格のたびに見るのか

**購読漏れはエラーを 1 件も出さない。** イベントが届かないだけなので、アプリからは
「そのイベントが発生しなかった」のと区別できない。

- コードに `case` を足すのは PR だが、**Stripe の endpoint の設定を変えるのは人の手**なので、両者は放っておくと必ずずれる
- stg の endpoint を更新して本番を更新し忘れる、が典型（本番だけ初期構築時のイベント一覧のまま凍結する）
- 届かないイベントによっては、割引の重複適用・救済処理の停止・消込の漏れなど、**金銭的な実害が静かに進む**

## 手順

1. **[A] コード ↔ manifest**（鍵不要）: コードが処理するイベントの一覧（manifest）と、webhook ハンドラの `case` が一致すること。
   PR のテストでも同じことを見ている
2. **[B] stg と突き合わせる**（PR② をマージする前）: test 鍵で `GET /v1/webhook_endpoints` を読み、
   **1 つの endpoint が manifest の全イベントを購読している**ことを確かめる
3. **[C] 本番と突き合わせる**（PR③ / 選択リリースをマージする前・**運用者が実行する**）: live 鍵で [B] と同じことを行う。
   **エージェントは live 鍵を扱わない**

突き合わせのスクリプトを作るなら、終了コードを 3 値にする: `0` 一致 / `1` **購読漏れ** / `2` 判定不能（鍵が無い・読めない）。
**`2` を「たぶん大丈夫」と読まない。** 読めなかっただけで、何も検査できていない。
live 鍵では、明示のフラグが無い限り動かないようにする。

## 赤くなったとき

出力に足りないイベント名が並ぶ。Stripe ダッシュボード → 開発者 → Webhooks → 該当 endpoint → 「イベントを選択」で追加する
（本番は運用者の許可を得てから）。`case` を足したら manifest も同じ PR で足す。

## Connect を使う場合

- connected accounts のイベント（`account.updated` 等）は、**作成時に「接続アカウントのイベントをリッスン」を選んだ endpoint** にしか届かない。
  通常の endpoint とは別に作り、署名シークレットも別の環境変数で持つ
- **API は endpoint が通常か Connect かを返さない**ので、[B] / [C] は Connect endpoint の漏れを検出できない。
  Connect のイベントを足す昇格では、stg / 本番それぞれでダッシュボードを目視して確かめ、PR 本文に記録する

## 限界

- **実行しなければ何も検出しない。** CI では走らない（鍵が無い）。このステップをチェックリストから外すと、スクリプトは存在するだけになる
- stg で緑でも、本番の endpoint については何も言っていない（[C] が要る）
- 署名シークレットのずれは見ない（こちらは届いても 400 になるのでログに出る）
- 取りこぼし（配送失敗）の後始末は日次の照合（reconcile）の担当。この検査は「そもそも届くようにする」側
